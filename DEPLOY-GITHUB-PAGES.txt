ALSherif STORE PS4 HOST — GITHUB PAGES QUICK DEPLOY

IMPORTANT: This archive is already flattened for GitHub Pages.
When extracted, index.html should be directly inside the extracted folder, not inside another nested project folder.

A. CREATE THE GITHUB REPOSITORY
1. Sign in at https://github.com/new
2. Repository name: alsherif-store-ps4-host (or another name you prefer).
3. Choose Public if using GitHub Free. This makes the source and site publicly accessible.
4. Do NOT initialize with a README, .gitignore, or license; the project already contains these files.
5. Click Create repository.

B. PUBLISH THE EXTRACTED FILES (WINDOWS / BEGINNER-FRIENDLY COMMAND LINE)
1. Install Git for Windows from https://git-scm.com/download/win if the `git` command is not available.
2. Extract this ZIP into a simple path, for example C:\Alsherif-Store-GitHub-Pages-Ready.
3. Open that extracted folder. Confirm index.html is visible at the same level as README.md and folders named `includes` and `src`.
4. Click the File Explorer address bar, type `powershell`, then press Enter.
5. Copy these commands one at a time, replacing YOUR-GITHUB-USERNAME with your real GitHub username:

   git init
   git add .
   git commit -m "Publish Alsherif Store PS4 host"
   git branch -M main
   git remote add origin https://github.com/YOUR-GITHUB-USERNAME/alsherif-store-ps4-host.git
   git push -u origin main

If Git asks for your name/email before committing, set them with:
   git config --global user.name "Your Name"
   git config --global user.email "YOUR-GITHUB-EMAIL"
Then run the `git commit ...` command again. When prompted to sign in for `git push`, complete GitHub's authentication flow. Do not put passwords or personal access tokens inside the commands.

If you chose a different repository name, update the URL in `git remote add origin` to match it exactly. If a `remote origin already exists` message appears, stop and check `git remote -v` instead of adding it again.

C. ENABLE GITHUB PAGES
1. Open your repository on GitHub.
2. Go to Settings → Pages.
3. Under Build and deployment, set Source to `Deploy from a branch`.
4. Set Branch to `main` and folder to `/(root)`, then click Save.
5. Wait for the Pages build/deployment to complete. Under Settings → Pages, click `Visit site` when the URL appears.
6. For username `YOUR-GITHUB-USERNAME` and repository `alsherif-store-ps4-host`, the address will usually be:
   https://YOUR-GITHUB-USERNAME.github.io/alsherif-store-ps4-host/

D. OPEN IT ON YOUR PS4
1. First test the exact published URL on a PC or phone. Confirm the banner appears, styling loads, and there are no 404s for JS/CSS/images.
2. On the PS4, open the web browser and enter the same HTTPS URL.
3. If the host asks whether to switch from HTTPS to HTTP, choose Cancel/No to remain on HTTPS. GitHub Pages redirects HTTP back to HTTPS, so switching is not appropriate for this host.
4. Wait for the host's firmware-based cache process if it appears, then use only options compatible with your own firmware.
5. Bookmark the page on the PS4 for later.

IMPORTANT LIMITATIONS
- Do not upload the ZIP as a single file and expect GitHub Pages to extract it. Extract it on your PC first, then push all the extracted website files with Git.
- The public GitHub repository and Pages website expose the website source and included payload files to anyone. Do not add credentials or personal data.
- GitHub Pages is HTTPS-only in practice. This host also has local payload-delivery features that send binaries to HTTP endpoints on the PS4 (ports such as 9090/9021). Browser mixed-content/security rules may block those features from a hosted HTTPS page. If remote payload delivery or scanning fails, that does not necessarily mean the exploit page itself failed; use a compatible local HTTP host/server for those functions, as documented upstream.
- Static GitHub Pages is not a backend server. It does not provide PS4-Websrv endpoints or a local-network scanner backend by itself.
- A cache/exploit page is firmware-dependent. Successful page deployment is not proof that every included exploit, GoldHEN build, or payload works on your console. No physical PS4 test has been performed as part of this archive preparation.
- Keep LICENSE and SOURCE-AND-LICENSE.md when publishing modified upstream code. Review the AGPL-3.0-or-later terms and provide source as required.
